# Island agent protocol `island-agent/1`

Transport: Unix-domain socket `<runtimeDir>/p-XXXXXX/s` (dir 0700, socket 0600, path ≤ 107 bytes).
Framing: one JSON object per line, split on LF (0x0A) only. Inbound ≤ 256 KiB (hello ≤ 4 KiB),
max 240 frames/min per client, max 4 clients (see "Client slots"), outbound queue ≤ 1 MiB (slow client is dropped).
Outbound text invariant (K2-05 U2 follow-up): NO outbound line ever carries a lone UTF-16 surrogate —
`encodeServerFrame`, the single outbound encoder, replaces any lone surrogate in any string with U+FFFD
(a `\udXXX` escape for a lone half is what the island's serde_json rejects, dropping the connection),
and every chunk/clip of outbound text (`message_delta` chunking, history clips) cuts on whole code points,
never between the two halves of a surrogate pair.
Implementation: `src/protocol.cjs` (codec/validators/translation), `src/server.cjs` (`IslandServer`).

## Handshake

1. Client sends within 3 s: `{"type":"hello","protocol":"island-agent/1","token":"<per-launch capability>"}`.
   The token is generated by the host (`IslandServer.generateToken()`), compared timing-safely.
   Any failure (timeout, bad token, bad protocol, malformed) closes the socket with no detail.
2. Server sends `ready`. Every server frame carries `seq`, a per-client counter starting at 1.

## Client → server

| type | fields | notes |
|---|---|---|
| `send` | `text`, `images?[{data(base64),mimeType}]`, `requestId?` | `busy` error while a turn runs; completion is `agent_settled`, not the prompt response. `requestId` (`[A-Za-z0-9_-]{1,64}`, anything else is `bad_request`): see "Recorded prompts" |
| `steer` | `text`, `requestId?` | only while busy (`not_busy` otherwise); `requestId` as for `send` |
| `abort` | – | Cancels a running turn; its child is recycled before another prompt. An ACK alone never frees busy. Idle abort still reaches Pi. |
| `set_paused` | `paused: bool` | Global pause switch (#379); see "Global pause" |
| `new_conversation` | – | **Refused** with a fixed `error{conversations_off}` (K2-05 T4 U1): the island keeps ONE continuous chat (L3/L4/L7, Gentle Dot's `conversationsOn` gate). The refusal precedes every other gate (busy, paused included) and no command ever reaches the engine |
| `get_history` | – | replies `history{messages,hasEarlier}` — the newest page of the open chat; see "History frames". `unavailable` while the engine is not ready or holds no open session |

Ids are canonical (no leading zeros): a non-canonical or non-page-id `before` is `bad_request`; a canonical id that names no turn — `sN-0`, a turn beyond what that file ever held, or an index past the chain — yields an EMPTY page with `hasEarlier:false` (the island keeps what it shows) |

| `ui_response` | `id`, one of `value` / `confirmed` / `cancelled` | answers an `ask`; validated against the pending ask |

| `auth_cancel` | `flowId` | |

### Provider settings frames (additive, v0.2)

Same protocol id; clients that never send these frames are unaffected. Every string below is validated
strictly; unknown fields are dropped; invalid frames get `error{bad_request}`. `STRICT_ID` =
`^[a-z0-9][a-z0-9._-]{0,63}$`. "Label" = non-empty after trim, ≤ 80 chars, no control characters (tab/newline included).

| type | fields (type, bounds) | success | error codes |
|---|---|---|---|
| `account_create` | `provider` STRICT_ID; `label` label; `accountId?` STRICT_ID (derived from the label when absent) | reply `account{account}` to the caller, then broadcast `accounts` | `unavailable` (no account manager), `busy` (a sign-in or account change is running), `failed` (duplicate id, invalid input) |
| `local_account_create` | `label` label; `accountId?` STRICT_ID (derived from the label); `baseUrl` string ≤ 200 passing the **loopback policy** below; `modelIds` array of 1–32 unique strings (duplicates are `bad_request`), each 1–200 chars, no control chars, not whitespace-only | reply `account{account}` (with `local:true`) to the caller, then broadcast `accounts` | `bad_request` (invalid shape, URL or model ids), `unavailable`, `failed` (duplicate id, provider id `local-<accountId>` longer than 64) |
| `local_endpoint_set` | `accountId` STRICT_ID; `baseUrl`, `modelIds` as above | reply `account{account}` to the caller, then broadcast `accounts` | `bad_request`, `unavailable`, `busy` (a turn runs or a selection is in flight **and** the account backs the active profile; or a sign-in runs), `failed` (unknown account, **not a local account**) |
| `account_remove` | `accountId` STRICT_ID | broadcast `accounts` | `unavailable`, `busy` (sign-in in progress), `failed` (unknown account, **in use by a saved profile**) |
| `account_logout` | `accountId` STRICT_ID | broadcast `accounts` (plus `profiles` and `agent_state` when it deactivates) | `unavailable`, `busy` (sign-in in progress; or, when the account backs the active profile and no safe point is reached within the bound after the in-flight turn was interrupted — see "Live interruption" below; in that case the credential is untouched), `failed` |
| `account_status` | `accountId` STRICT_ID | reply `account{account}` (re-reads configured/authMethod from the account store; caller only) | `unavailable`, `failed` |
| `profile_save` | `id` STRICT_ID; `label` label; `role` STRICT_ID; `accountId` STRICT_ID; `provider` STRICT_ID; `modelId` 1–200 chars, no control chars; `thinkingLevel?` ∈ `off,minimal,low,medium,high,xhigh,max` (default `medium`) | broadcast `profiles` | `unavailable`, `failed` (unknown account, provider ≠ account provider, too many profiles) |
| `profile_remove` | `id` STRICT_ID | broadcast `profiles` | `unavailable`, `failed` (unknown profile, profile is the active one) |
| `profile_deactivate` | – | deactivates the ACTIVE profile (preserves a refreshed credential into its account, removes the private agent `auth.json`/`models.json` and the model defaults from `settings.json`, clears the active marker, restarts the engine; every file is restored on failure). No active profile: no-op. Then broadcast `profiles` and `agent_state` | `unavailable`, `busy` (turn running, another switch/deactivate in flight, or the engine reports busy), `failed` |
| `auth_state` | – | reply `auth_state{flow}` | `unavailable` |

`auth_start`, `auth_reply`, `auth_cancel`, `auth_started`, `auth_prompt`, `auth_event`, `auth_done` are unchanged;
`accountId`/`method` appear nowhere new on those frames, only in `auth_state`.

### Global pause (additive, #379)

One global switch, backend only this round (a UI card comes later):

| type | fields | success | error codes |
|---|---|---|---|
| `set_paused` | `paused`: required boolean (extras dropped, non-boolean is `bad_request`) | persists atomically (0600, other config keys kept), then broadcasts `agent_state` to ALL clients (caller included, once) | `failed` (persistence failure; the previous state stays in memory AND on disk) |

Setting the same value again replies the current `agent_state` and changes nothing. While `paused` is true the
daemon admits nothing new:

- REFUSED with a new closed error code `error{paused}`: `send`, `steer` (agent-turn admission)
  and `agent_connect`, `connectors_list`, `agents_list` (each spawns a process: a tool/connector call).
  `new_conversation` is NOT on this list since K2-05 T4 U1: it is refused `conversations_off` regardless of the
  pause state (the refusal precedes every gate).
- STILL ALLOWED: `abort` and `agent_disconnect` (stopping work is always possible), every read-only query
  (`status`, `accounts_list`, `providers_list`, `models_list`, `profiles_list`, `settings_get`, `mcp_import_preview`,
  `agents_list` while unpaused, `auth_state`), and all account/profile/settings/auth verbs. Scheduled tasks have no
  admission path in the daemon yet; when one exists it must honor this switch.
- In-flight work is interrupted at the next safe point (#378): pausing while a turn is active cancels the turn
  through the engine's cancellation path (reason `paused`): admission closes, open asks resolve, one sanitized
  warning `toast` explains the pause ("La pausa interrumpió el turno del agente."), the child is recycled and the
  session reopens; no prompt is ever replayed. Idling pause sends nothing. `agent_state{paused:true}` is broadcast
  immediately either way.

The pause is persisted as the strict boolean `paused` key in `config.json` and restored at the next daemon boot
(a hand-edited non-boolean is `invalid config: paused`, like every other key). `ready.state`, every `agent_state`
and the daemon `status` carry `paused`. A `config.json` hand-edit of `paused` is picked up at the next daemon
boot only; the wire verb is the runtime path.

Server → client (new):

| type | fields |
|---|---|
| `account` | `account{accountId (≤64), label (≤80), provider (≤64), authMethod: oauth\|api_key\|none, configured: bool}` — same DTO as one `accounts` entry |
| `auth_state` | `flow`: `null` or `{flowId (≤128), accountId (≤64), method: oauth\|api_key, phase: starting\|prompt\|progress\|done}` |

`auth_state.phase` is derived by the server from the last `auth_*` frame of the current flow: `starting` after
`auth_started`, `prompt` after `auth_prompt`, `progress` after `auth_event`, `done` after `auth_done` (success, failure
or cancel; read `accounts` for the result). The last flow stays reported as `done` until the next `auth_start`;
`flow:null` means no flow was seen since the daemon started. A late-connecting client uses it to resume, but pending
prompts are not replayed (`auth_cancel` and restart the flow if the prompt was missed).

### Settings frames (additive, hotkey)

| type | fields | success | error codes |
|---|---|---|---|
| `settings_get` | – | reply `settings` to the caller | `unavailable` (no settings dependency) |
| `settings_set` | `hotkey`: string (1–40 chars) or `null` (clear) | persists atomically (0600, other config keys kept), then broadcasts `settings` to ALL clients (caller included, once) | `bad_request` (hotkey violates the grammar), `failed` (persistence failure), `unavailable` |

Server → client: `settings{hotkey: string|null}` (`null` = unset). It is also broadcast when a config.json edit is picked up (SIGHUP).
An invalid `hotkey` hand-edited into config.json is ignored on read: `settings.hotkey` is `null` and the daemon's `status` has `hotkeyInvalid: true` (never the value). `settings_set` stays strict.
Frames with a non-string/over-long `hotkey` are rejected as `bad_request` before reaching the daemon.

**Grammar (strict).** `Modifier+(Modifier+)*Key`. Modifiers: `Ctrl`, `Alt`, `Shift`, `Super`; at least one, no duplicates.
Key: exactly one of an ASCII letter or digit, `F1`–`F24`, or `Space, Enter, Tab, Escape, Backspace, Delete, Insert, Home, End,
PageUp, PageDown, Up, Down, Left, Right`. No whitespace, control or non-ASCII characters; max 40 chars. Input is
case-insensitive and canonicalized: modifiers in `Ctrl+Alt+Shift+Super` order, letters upper-cased, named keys in the spelling above.

```
→ {"type":"settings_set","hotkey":"super+ctrl+space"}
← {"type":"settings","hotkey":"Ctrl+Super+Space","seq":12}     (to every client)
→ {"type":"settings_set","hotkey":"Space"}                      ← {"type":"error","code":"bad_request"}
→ {"type":"settings_set","hotkey":null}                         ← {"type":"settings","hotkey":null}
```

The daemon only validates and stores; registering the global shortcut is the host's job.

### Connectors frames (additive, read-only)

| type | fields | success | error codes |
|---|---|---|---|
| `connectors_list` | – (extra fields dropped) | reply `connectors` to the caller only | `unavailable` (no connectors dependency), `failed` (any problem; generic, no detail), `rate_limited` (counts toward the 240 frames/min limit) |

Server → client, exact schema (every object rebuilt from an allowlist; unknown keys dropped at every level):

```
{"type":"connectors","schema":"abito-connectors/view/1","seq":N,
 "catalog":[ {key, label, reads, sends, auth, fields:[{key,label,secret,optional}], guide?:{steps:[..],note?}, read_only_tools_count} ],
 "connectors":[ {id, label, catalog_key?, mode, enabled, status:{state, code?}, revision, configured} ]}
```

Bounds: `catalog` ≤ 32 entries; `key`/`id`/`catalog_key` ≤ 64 (`[A-Za-z0-9][A-Za-z0-9_-]*`; field `key` also allows `.`);
`label` ≤ 128, `reads`/`sends`/guide step/note ≤ 512, all non-empty with NO control, bidi/format or line-separator characters;
`auth` ∈ `none, provider_oauth, user_oauth`; `fields` ≤ 8; `guide.steps` ≤ 16; `read_only_tools_count` integer 0..1000;
`connectors` ≤ 256; `mode` ∈ `read_only, read_and_send` (anything else → `unknown`); `status.state` ∈
`connected, needs_setup, failed, disabled` (anything else → `unknown`); `status.code` ≤ 64 chars `[a-z0-9_]`; `revision` integer ≥ 0.
Wrong types or bounds are rejected, never coerced: the whole request answers `error{failed}`.

How it is produced: the daemon spawns the connectors CLI at the ABSOLUTE `connectorsCommand` (set by the host to the installed
`abito-connectors` binary; no default, no bare names; unset → `unavailable`, nothing executes). One snapshot = TWO processes
(`catalog` and `status --dir <connectorsDir>`). Before each spawn the target is checked (regular file after realpath, executable,
owned by the user or root, not group/world-writable, parent chain not world-writable without sticky); failure → generic `failed`.
`shell:false`, no stdin, own process group, cwd = island, environment = locale allowlist + fixed `PATH=/usr/bin:/bin` + private HOME
(no `PI_*`, no provider keys). The configured binary is trusted code run as the user.
5 s hard timeout then SIGKILL of the whole process group (grandchildren included, also on oversize/failure), stdout capped at 256 KiB (exceeded → killed and failed), stderr drained and never surfaced,
no retries. Exit ≠ 0, timeout, oversize, invalid UTF-8, not exactly one JSON line or a `schema` other than
`abito-connectors/view/1` all produce the same generic failure. The CLI output is REVALIDATED here, it is not trusted.

Emission cap: the daemon replies at most 128 `connectors` and 32 `catalog` entries, and a serialized frame of at most 200 KiB
(well under the 256 KiB frame class and the outbound limit). Over any cap the request answers generic `failed`: nothing is truncated
silently. (The CLI-side bounds, up to 256 connectors, stay as validation limits.) Field keys / ids `__proto__`, `constructor`, `prototype` are rejected.

Limits: at most ONE snapshot (two spawns) in flight (concurrent clients share it) and at least 1 s between snapshots; inside that window
the last outcome (frame or failure) is served from memory. A client therefore cannot make the daemon run more than 1 snapshot per second. `status.connectorsAvailable` is true only when a view is wired (valid `connectorsCommand` configured).

**What these data are.** The `connectors_list` result is the PERSISTED `connectors.json` view, read-only. It is NOT live and can lag the running host; its `connectors` frame has no `live` field. Separate H2c control commands use the live host and mark their `connectors` frame with `live:true`. The persisted view itself has no pending approvals or mutation actions. Neither view allowlists upstream URLs/commands/env/headers, OAuth settings or proxy capabilities; setup values use only the existing one-way `auth_reply` path described under H2c.

### MCP import preview frames (additive, read-only, #381)

| type | fields | success | error codes |
|---|---|---|---|
| `mcp_import_preview` | – (extra fields dropped) | reply `mcp_import` to the caller only | `unavailable` (no usable HOME or no dependency), `failed` (any problem; generic, no detail), `rate_limited` (counts toward the 240 frames/min limit) |

Server → client, exact schema (every object rebuilt from an allowlist; unknown keys dropped at every level):

```
{"type":"mcp_import","schema":"abito-mcp-import/preview/1","seq":N,
 "files":[ {source, status} ],
 "servers":[ {source, name, scope?, transport, command|url, status, fields?:[{key,label,secret,optional}], reason?} ],
 "truncated": bool}
```

What it is: a PREVIEW of the MCP servers configured in other desktop clients, for the user to accept. Nothing is
imported here; an explicit accept verb (future unit, needs host persistence) is the only path that ever writes.

How it is produced: the daemon READS, at request time, the known config locations of Claude Desktop, Claude Code,
Cursor and VS Code under the daemon's REAL HOME (never the island home; no config key; no execution, nothing written,
no caching). Known locations: `~/.config/Claude/claude_desktop_config.json` or
`~/Library/Application Support/Claude/claude_desktop_config.json` (linux/darwin), `~/.claude.json` (root `mcpServers`
plus per-scope `projects.<path>.mcpServers`), `~/.cursor/mcp.json`, `~/.config/Code/User/mcp.json` or the darwin
`Library/Application Support/Code/User/mcp.json` (`servers` or `mcp.servers`, with `inputs`). A missing file is simply
absent from `files`. Mapping semantics mirror the pure importer of apps/desktop-connectors (`import.rs`):
stdio/http classification, SSE/unknown/conflicting/invalid entries rejected with a closed `reason`
(`sse_transport, conflicting_transports, unsupported_transport, invalid_entry`), `${input:}`/`${env:}`/`${userHome}`
handling, and a whole-document duplicate-object-key rejection (a repeated key anywhere makes the file `malformed`).

`files` reports only EXISTING files: `status` ∈ `ok, malformed, unreadable, too_large, too_many`
(> 200 entries in one document, mirroring the importer cap); per-file problems are reported, never fatal.
`servers` is the deterministic (source, name, scope) sorted preview across all files:
`source` ∈ `claude-desktop, claude-code, cursor, vscode`; `name` ≤ 128 chars; `scope` ≤ 256 (Claude Code project key);
`status` ∈ `ready, needs_setup, rejected`; `transport` ∈ `stdio, http` with exactly `command` (stdio) or `url` (http)
for ready/needs_setup entries, and `reason` for rejections; `fields` (needs_setup only, ≤ 16) names the values the
host must collect — the key may be an input id or `env:<NAME>`.

**What these data are NOT.** Env values, header values, args, file contents and file paths never appear in the frame:
the scan collects them internally to classify the entry and then drops them. `${userHome}` is expanded to HOME;
URLs are kept verbatim (a URL carrying an `${input:...}` placeholder makes the entry `needs_setup`). The scan is
read-only and cannot mutate anything.

Emission cap: at most 8 `files`, 128 `servers` and a serialized frame of 200 KiB; over any cap the request answers
generic `failed` (nothing is truncated silently — the scan result carries `truncated: true` when the preview cap cut
the server list). `status.mcpImportAvailable` is true only when a usable HOME was found at daemon boot.

### Sessions frames (additive, read-only, #360)

| type | fields | success | error codes |
|---|---|---|---|
| `sessions_list` | – (extra fields dropped) | reply `sessions` to the caller only | `unavailable` (no dependency), `failed` (any problem; generic, no detail), `rate_limited` (counts toward the 240 frames/min limit) |

Server → client, exact schema (every object rebuilt from an allowlist; unknown keys dropped at every level):

```
{"type":"sessions","schema":"abito-sessions/view/1","seq":N,
 "sessions":[ {id, kind, cwd, state, origin} ],
 "truncated": bool}
```

What it is: the LIVE agent sessions running on this machine (Pi first), discovered by a bounded read-only scan of
Linux `/proc` process metadata. It answers "who is working, from where" — never what they are doing.

Row fields: `id` is a derived anonymous id `s-<8 lowercase hex>` (SHA-256 of pid + process start time; stable while
the process lives, never the raw pid); `kind` ∈ `pi, claude-code, codex, opencode, gemini` (the closed table of known
agent binaries matched on the basename of an early argv entry); `cwd` is the BASENAME of the process's working
directory (≤ 64 chars, no separators, no control characters; `null` when unreadable — never the full path);
`state` ∈ `running, sleeping, stopped, zombie, unknown` (the /proc state char mapped); `origin` is the terminal host
when a KNOWN one appears on the parent chain (`herdr, tmux, screen, kitty, alacritty, gnome-terminal, konsole,
xterm, wezterm, ghostty, code`; ≤ 32 chars) or `null` when none is found.

**What these data are NOT.** Command lines, arguments, environment, full paths, pids, usernames and any other
process detail never appear in the frame: the scan reads them internally to classify the process and then drops
them. Non-Linux platforms scan nothing (an honest empty result). The scan is bounded (≤ 4096 pids examined,
≤ 64 sessions; over the session cap `truncated: true`), reads only same-user process metadata and never writes,
spawns or executes anything.

Emission cap: at most 64 `sessions` and a serialized frame of 64 KiB; over either cap the request answers generic
`failed` (nothing is truncated silently). Rows are revalidated field by field on the wire; any off-vocabulary value
makes the whole request `failed`.

Limits: at most ONE scan in flight (concurrent clients share it) and at least 2 s between scans; inside that window
the last outcome (frame or failure) is served from memory, so clients cannot make the daemon hammer `/proc`.
`sessions_list` is a read: it still answers while the global pause is on.

### Agents frames (additive, H2b: connect/disconnect the Claude Code and Codex hooks)

| Client → server | Fields | Reply / errors |
|---|---|---|
| `agents_list` | – | reply `agents` to the caller; `unavailable` (no dependency), `failed` |
| `agent_connect` | `agentId` ∈ `claude-code, codex, statusline, opencode`, `plan_hash` (64 lowercase hex; required for statusline, optional for legacy ids) | broadcast `agents` to ALL clients (first a `working` state, then the result); `busy` while any operation runs; `bad_request`, `unavailable`, `failed` |
| `agent_disconnect` | `agentId` | same |

```
{"type":"agents","seq":N,"agents":[{"id":"claude-code","name":"Claude Code","state":"not_connected","backup":false,"detail":null,
  "plan_hash":"<64 hex>","summary":"Adds the Abito hooks (PermissionRequest, Stop) to ~/.claude/settings.json. A backup is made first.",
  "reviewable":true,"trust_review":false}, ...]}
```

- `state` ∈ `not_connected, connected, outdated, working, unavailable, error`. `detail` is `null` or the CLOSED set
  `config_invalid, not_writable, backup_failed, plan_changed, audit_unavailable, install_failed, unsupported_platform`. Windows automatic hook installation returns `unavailable` with `unsupported_platform` without spawning the installer; this is not evidence that hooks are installed. **Tauri lane: `plan_changed`,
  `audit_unavailable` and `install_failed` are new members of that set and must render.** Extra fields are additive.
- Ids/names are a fixed table (`claude-code` "Claude Code", `codex` "Codex", `statusline` "Uso del plan (relay)", `opencode` "OpenCode"). `opencode` is ALWAYS `unavailable`
  (not installable yet) and never spawns anything. Without `hookInstallerBin` every agent is `unavailable` (`detail: null`).
- `plan_hash`, `summary`, `reviewable`, `trust_review` appear only for `not_connected` / `outdated` (and on `error/plan_changed`, which hands back the NEW plan to re-show).
  `summary` is a closed template (never file content): `Adds the Abito hooks (PermissionRequest, Stop) to ~/.claude/settings.json. A backup is made first.`
  (`Updates the Abito hooks in <file>. A backup is made first.` when outdated; Codex appends ` Codex will ask you to trust them in /hooks.`;
  not reviewable appends ` This change is large: review it in the file.`). `reviewable` is false when the installer's diff has hidden lines or sanitized lines.
  `backup` is true when a `<target>.abito-backup-*` regular file exists next to the target. Right after a successful Codex connect the entry also carries `trust_review: true` (hooks stay inactive until trusted in `/hooks`).
- **Plan shown when the button appeared.** The island keeps the `plan_hash` of the `agents` frame it rendered and sends it in `agent_connect`.
  The daemon previews again; a different fresh plan => `error/plan_changed`, NOTHING is applied, the new `plan_hash`/`summary` come back. Without
  `plan_hash` the fresh preview is applied for legacy ids only (opt-in; the human then saw nothing). Statusline rejects a missing hash as `bad_request`. Disconnect applies the fresh REMOVE plan (backup first; other tools' hooks are never touched).
- One operation at a time, GLOBALLY: while it runs the agent is `working` (`agents_list` shows it) and further connect/disconnect get `error busy`.
  `agents_list` is cached 1 s and single-flight (each list = one read-only preview per installable agent). Frames count toward the 240/min per-client limit.
- Every failure is generic: no stderr, stdout text, path or file content reaches the wire.

**Notify-only integration (#467, L32e).** Statusline uses `~/.claude/settings.json`, through the same installer CLI with no wire-supplied paths/argv/env; it has exactly one entry, `statusLine`. Each entry accepts only `add`, `replace`, `remove`, `keep` (removal without our marker is `keep`). All-keep means connected, all-add not_connected, otherwise outdated, exactly as for Claude/Codex. Statusline's summary says it adds the relay in `~/.claude/settings.json`, the existing status line keeps working because the relay prints it, and a backup is made first. The statusline installer saves/restores the previous status line at `~/.abito/statusline-previous.json` (0600), as in the interactive flow. Script paths are derived from the installer's package, never supplied by the wire. It does not spawn when `hookInstallerBin` is unset.

**Recap (removed in 0.2).** `recap` is no longer an agent id: `agent_connect`/`agent_disconnect`/`hooks_install`/`hooks_remove` with it are refused like any unknown id. **Endpoint handoff consumed by hooks (enforced rules).** An explicit `ABITO_DESKTOP_SOCKET` wins after endpoint-shape validation and causes no `endpoint.json` read. Otherwise runtime selection is ordered: `ABITO_SOCKET_DIR` (when set, absolute, normalized and non-root), else `$XDG_RUNTIME_DIR/abito-island` only when `XDG_RUNTIME_DIR` is absolute, normalized and non-root, else `/run/user/<uid>/abito-island`.

The reader accepts `<runtime>/endpoint.json` only as a regular, non-symlink file owned by you, mode exactly `0600` including no special bits, a single hard link, and at most 4096 bytes. Its complete text must equal `JSON.stringify(parsed)` or that exact compact serialization plus one LF; it has exactly `v`, `endpoint`, `pid` (with `v: 1`). Duplicate keys, escaped key names, pretty printing, other whitespace and CRLF are refused. The Rust producer at `apps/desktop-tauri/src/handoff.rs` writes compact one-line `serde_json` plus LF as `{"endpoint":"<..>","pid":N,"v":1}\n`; the alternate `v,endpoint,pid` order is accepted as well.

`pid` must be a positive valid pid with `/proc/<pid>` present and `/proc/<pid>/stat` readable within 512 bytes. The state character is parsed after the last `)`; `Z` (zombie), `X`, malformed or unreadable state is refused. The optional `procStart` key (decimal string, field 22 of `/proc/<pid>/stat`) is verified when present: a different value is a recycled pid and the handoff is refused, and a malformed value or an unreadable start time fails closed. Without the key the check is existence/alive only, so pid reuse stays a residual risk until the island writes it (Tauri lane switch `WRITE_PROC_START`).

`endpoint` must be `<runtime>/p-<6 alphanumeric>/s`, at most 107 bytes, and a Unix socket. `readHandoff` invokes the same `verifyEndpoint` checks as the client. Every directory component is checked with `lstat`, must not be a symlink, must be owned by you or root, and must not be world-writable; the `<runtime>` and `p-<6 alphanumeric>` directories must be yours and exactly `0700`. The socket must be yours, exactly `0600`, and not a symlink. Thus a runtime beneath world-writable `/tmp` cannot host an island. The client verifies before connect and rechecks the socket's device/inode after connect; path re-pointing between handoff and connect is bounded by that dev/ino re-check, not eliminated. The trust model is same-uid: another process running as you can manipulate same-owner paths. Resolution does not connect or scan, and there is no fallback. Stale or unsafe handoffs mean unavailable (the terminal prompt stays in charge). For Codex the human must also trust the new hooks in `/hooks`.

#### Provider settings flow

1. `providers_list` → `providers` (what can be connected; `methods` ⊆ `oauth, api_key`).
2. `account_create{provider,label}` → `account` + broadcast `accounts` (new account, `configured:false`).
3. `auth_start{accountId, method:"api_key"|"oauth"}` → `auth_started{flowId}`.
4. `auth_prompt` (`secret:true` for a key) → the user answers with `auth_reply{flowId,promptId,value}`; OAuth adds `auth_event` (URL/device code). `auth_state` can be polled at any time.
5. `auth_done{ok}` (carries the safe account DTO on success).
6. `models_list{providerId,accountId}` → `profile_save{…}` → broadcast `profiles`.
7. `profile_select{id}` activates it (refused while busy); `profile_deactivate` returns to "no active profile".
   Cleanup: `profile_remove` (not the active one), `account_logout` (logging out the active profile's account also deactivates that profile, same guard as `profile_deactivate`; refused with `busy` before logging out), `account_remove` (not while a profile uses it).

**Security.** API keys travel only through the `auth_reply` secret-prompt path, go straight to the account manager
and the SDK helper, and are never echoed, logged, stored in a DTO or sent back. No frame carries a key, token,
`baseUrl`, header or environment value; errors are generic codes only. Private endpoints are the one
exception to "no URL on the wire": `local_account_create` / `local_endpoint_set` carry a loopback `baseUrl`
CLIENT -> SERVER only (see below); the daemon never sends it back.

Unknown/invalid post-handshake frames get `error{code:"bad_request"}`.

## Semantics and limits

- Pending asks: max 16, answered once; unanswered asks are cancelled toward the agent after 120 s.
- Engine restart/exit: `agent_state{status:"restarting"}`, open asks closed, no half-answer replay. Ordinary crash clears busy. A cancelled turn remains busy/unavailable until its replacement generation is ready.
- Full-turn technical defaults (Pi adaptation, not AG-UI/TanStack parity): 300,000 ms
  monotonic elapsed time from prompt submission and 32 observed Pi `turn_start`
  signals. Abort fires **on the 32nd start**, not after 32 completed cycles.
  RPC ACKs, text deltas, tools, steering, `agent_start`, `agent_end` and
  `turn_end` do not reset/finish the full-turn budget or count as starts.
- Time/start-limit expiry or explicit cancellation stops output/ask admission
  immediately, resolves outstanding asks on the wire, and sends one Pi abort.
  Existing sanitized warning `toast` and `agent_state` frames describe cutoff;
  no new frame/error vocabulary or budget fields are introduced.
  Settlement or a 2,000 ms drain grace always recycles the cancelled owned child.
  Abort ACKs cannot free admission; prompts and profile/session changes remain
  guarded until the replacement is actually ready. The private session persists,
  but no prompt is automatically replayed, including after ambiguous prompt ACK loss.
  Healthy natural `agent_settled` clears the timer without forced recycling.
- The island's `new_conversation` is REFUSED outright with the fixed `error{conversations_off}`
  before every gate (busy, paused included): Koda keeps ONE continuous chat and no reset ever
  reaches the engine from the island. The RUNTIME-level single-flight busy gate remains for the
  engine's own `new_session`/`switch_session` requests (the rotation and its fallback): a request
  during a cut-off generation or a session switch in flight is refused with `busy`/`not ready`, and
  concurrent send/profile/workspace/config changes retain their existing `busy` rejection without
  modifying stored config or action counters.
  A successful reset/switch response is checked against Pi's owned session
  identity via `get_state` before admission reopens; ordinary state reads remain
  usable. Lost ACK/timeout/failed response/child failure is ambiguous: the gate
  remains busy/unavailable through owned-child cutoff and verified replacement
  readiness. Recovery reopens the last verified session, never retries the reset
  or replays a prompt. Stop and generation changes invalidate old continuations.
- Late cancelled-child callbacks are discarded by child identity. Untagged Pi
  records cannot prove arbitrary cross-turn attribution, so cancellation never
  reuses the same process for a new turn. Async observation/cooperative abort
  **does not guarantee a hard provider-call/tool-side-effect ceiling** or undo
  completed effects. The defaults are Abito policy, not captured upstream constants.
- **Live interruption (#378).** When the user's permissions for the running agent change (revoked account access
  via `account_logout` of the account backing the active profile) or the global pause (#379) turns on, the in-flight
  turn is interrupted at the next safe point through the engine's cancellation path (`AgentEngine.interruptTurn`,
  reason `paused` or `access_revoked`): admission closes, open asks resolve, one sanitized warning `toast` with a
  fixed message explains why ("La pausa interrumpió el turno del agente." / "Se revocó el acceso: se interrumpió el
  turno del agente.") — engine text never reaches a client — the child is recycled and the session reopens with no
  replay. The `account_logout` permission change is applied only AFTER the safe point (the canonical `state().busy`
  guard clears, bounded by `interruptSafePointMs`, default 30000 ms): on timeout it answers `busy` and the credential
  and the active profile are untouched. `profile_deactivate` and `agent_disconnect` keep their existing guards.
- History/replay (K2-05 T4 U1): **implemented** as read-only pages of the open chat — see "History frames".
  A late client asks `get_history` once it has Handshook; the daemon never pushes an unrequested full history
  except after a rotation (below).
- Stale `p-*` socket dirs of dead servers (connection refused) are removed at start, with dev/ino checks.
- `ui_response` and `send` are not tied to the originating client; all clients share one session (a
  `send`'s `requestId` is echoed only to its sender, on the `user_message` of the prompt recorded for it).

### Client slots (K2-05 U2 follow-up, re-verified)

The cap is **4 clients**: the island's settings window, the chat, and one reconnect overlap, with the
daemon's own health probe (`classifySession`'s hello→ready exchange, used by `abito-island-daemon
status` and by the island to decide the daemon is alive) always answered. Three rules (F1, re-verify):

- **The cap counts ONLY authenticated live clients** — a set filled when a handshake is admitted and
  removed synchronously on close/destroy, so a dropped socket frees its slot immediately. Pre-hello
  connections (the separate bound below) never count against the cap.
- **The `ready` reply goes on the wire BEFORE the cap is evaluated.** A client the cap refuses
  receives its `ready` frame first and is then closed silently, like every other refusal — so its
  classification (the probe reads only that first frame) can never be `refused` by the cap while
  settings and chat are connected, not even under a burst of concurrent probes.
- **Pre-hello connections are bounded at connect time by a separate `maxHandshakes` bound (16)**,
  each also bounded by the handshake timeout: a surplus connect is destroyed silently at connect and
  is never counted anywhere. A hello'd client admitted by the cap releases its handshake-window
  bound at admission.

### History frames (additive, read-only, K2-05 T4 U1)

One continuous chat, read from the engine's whole rotated session chain (`engine.previousSessions` + the
open `sessionFile`, oldest file first). Port of the projection half of Gentle Dot's
`packages/daemon/src/conversations.ts` (MIT): user and assistant `type:"message"` records become display
turns; hidden `custom_message` handoffs and every other context-only entry NEVER appear; tool calls become
activities (closed kind `read/edit/run/search/memory/delegate/other`, title without tool names or
arguments, status `done`/`failed` from the engine's failed results); consecutive assistant messages join
into ONE turn; a user message's `<attachments>` block is split back into `text` and attachment chips.
ALL assistant text passes the white-label rewriter (`presentText`); the user's own text never does.

| frame | fields |
|---|---|
| `history` | `messages: HistoryMessage[]`, `hasEarlier: bool` |
| `earlier` | `before: string`, `messages: HistoryMessage[]`, `hasEarlier: bool` (the page ends just BEFORE the requested id) |

`HistoryMessage` = `{ id: "s<file>-<turn>", role: "user"\|"assistant", text, activities: Activity[],
attachments?: [{name,size,mime}], earlier?: true, clipped?: true }`. Ids are per-file (`s0-…` = the oldest file) and stay
STABLE while the chain grows, so `get_earlier` cursors survive a rotation. Messages of every file but the
last carry `earlier:true`.

- **Bounds.** A page is at most 100 messages (Gentle Dot's `HISTORY_PAGE`) and at most **192 KiB** of
  serialized frame — a named ceiling tied to the island reader's per-frame limit of 256 KiB
  (`FrameError::TooLarge` in `apps/desktop-tauri/src/agentclient.rs`), kept safely below it. The page is
  built from the newest message backwards and stops before the budget is exceeded; a single message
  larger than the budget is CLIPPED (its text, always already white-labelled, cut on whole code points;
  never a partial hidden name or a split surrogate), so one page always fits and size never becomes
  `error{failed}`. The frame rebuild clips each text to 64 KiB (the same ceiling the `send` verb
  accepts), caps activities at 100 (closed vocabulary, non-conforming entries dropped) and attachments
  at 16, and THROWS — the server answers `error{failed}` — if a rebuilt page still exceeds 1 MiB (a
  defense-in-depth ceiling the byte-bounded build never reaches). A message whose text was clipped — by
  the 64 KiB rebuild ceiling or by the page budget — carries `clipped: true` (K2-05 U2 follow-up: the
  clip is MARKED, never silent, so the island can show that history shows less than the live stream did;
  a text cut by the page budget is additionally marked `clipped: true` there too) — the cut always lands
  on a whole code point. A chain file that is missing or
  unreadable is skipped with a one-line daemon log (one over 64 MiB is skipped instead of blocking the
  read); torn/corrupt lines inside a file are skipped (the engine rewrites them as it appends).
- **Readiness.** While the engine is not `ready` or holds no open session, `get_history`/`get_earlier` answer
  `error{unavailable}` (retryable) — never an empty page, which would clear what the island shows.
- **Chain files are owned.** A chain file is read only when it is a regular, non-symlink, owned file
  directly inside the engine's private sessions dir (the runtime's `isOwnedSessionFile` rule) — a
  planted symlink or an outside path is dropped with a one-line log, never read — and `linkSessions`
  refuses such paths BEFORE a chain entry is persisted to `state.json`.
- **Freshness.** `get_history` carries Gentle Dot's `currentHistory` round trip (bridge.ts:1131-1145):
  one engine `get_state` round trip makes sure every message announced so far is already on disk, and
  the page is read again (bounded) when a message was announced during that round trip. `get_earlier`
  reads directly, as upstream does.
- **Rotation re-broadcast.** When a rotation (or its fallback `new_session`) replaces the open session and
  the new one already carries its chain, the daemon re-broadcasts ONE `history` frame per confirmed
  session change to every connected client: the same chat, now marked earlier (Gentle Dot
  bridge.ts:1124-1129). The broadcast fires on the engine's `session_changed` (chain present, engine
  ready — including a crash-recovery reopen, whose emit now fires only once ready) and `sessions_linked`
  (linked file == open session) events, so the fallback's confirmed-but-unlinked window never
  broadcasts an empty page. When the rotation's switch CONFIRMS but its verification fails and the
  fallback runs, TWO frames are broadcast: the confirmed seed's session change, then the fallback's
  linked fresh session.

### Recorded prompts (additive, K2-05 bind by id)

Port of Gentle Dot's `send{requestId}` dedupe (bridge.ts:399, 500 remembered ids) and its
`user_message` broadcast (bridge.ts onMessageStart, MIT). A client never has to infer which recorded
prompt is its own — not by counting engine cycles, not by matching text.

- **`requestId` on `send`/`steer`** (optional, closed grammar `[A-Za-z0-9_-]{1,64}`). A requestId the
  daemon has already seen (the last 500) makes the frame a silent no-op — no error, nothing reaches the
  engine — so a client never sends the same prompt twice. The check runs right after the `/gentle:`
  refusal, before every other gate, but an id is only REMEMBERED once its request passed the transient
  gates (engine ready, no session switch, `busy`/`not_busy`, pause): dispatched to the engine or held for
  a rotation. A request those gates refused (or the `/gentle:` refusal) leaves its id unspent, so the
  client may retry with the same id; a request the engine itself rejected stays spent (a lost ACK may
  already have started work). Each `error` answering a `send`/`steer` that carried a `requestId` echoes
  it, to its sender only, so the client never guesses which of its commands a refusal answers (frame-
  level refusals — `rate_limited` drops, undecodable frames — carry none).
- **`user_message`** is broadcast to EVERY client each time the engine starts recording a user message
  (Pi's `message_start`, role `user`): the island's own prompts, other clients' prompts, held prompts
  delivered after a rotation, consumed steers, and an extension's own user messages alike.
  - `messageId` is the page id the history frames give that same prompt (`s<open file index>-<row>`), so
    it joins with `history`/`earlier` exactly. The daemon counts the open file's display rows from the
    engine's message events since its last idle read of the file — never by reading the file while the
    engine writes it — and sends no `user_message` when that count is not known (after a cancelled turn,
    an engine restart or a session change, until the next prompt it dispatches).
  - `requestId` is echoed ONLY on the copy sent to the client whose `send`/`steer` the engine recorded
    (not a secret, but nobody else's correlation). The dispatched prompt is the run's first recorded
    user message whose text is its own; steers are matched by text in order (Pi removes a consumed
    steer from its queue by text); a recorded text that matches no pending steer falls back to the
    dispatched prompt (a template expansion changes the recorded text), and once no prompt is pending,
    to the oldest pending steer (a steer's template expansion; Pi records its queue in order) — only
    while every pending steer is the same client's: with steers of two clients waiting, an unmatched
    record is announced without any `requestId` rather than risk naming another client's request. Prompts
    held during a rotation are dispatched one after another when the switch settles; each keeps its own
    request, so the engine refusing a later one (it runs one turn at a time) forgets only that one: the
    delivered prompt keeps its sender's `requestId`, the refused sender gets `failed` and no `requestId`.
    A request the engine refused (the `prompt`/`steer` request failed), and every request still pending
    when the run settles or the engine goes away, is forgotten: it never names a later record. An
    unmatched record (an extension's own message) carries no `requestId`.
  - `text` is the user's own text (never white-labelled), split from its `<attachments>` block like
    history and clipped the same way (64 Ki chars, `clipped:true`). The frame is byte-bounded like one
    history page (192 KiB, measured with every field in place: `clipped`, `requestId`, the largest
    `seq` and the LF; under the island reader's 256 KiB): a longer text is cut on whole code points and
    marked `clipped:true`.

## Private memory (K2-05 T1c, the only mode)

Koda's memory is ALWAYS private — Gentle Dot's private mode (its `packages/daemon/src/isolation.ts`,
`privateMemory`, MIT), with no user-store mode. The engine child gets `ENGRAM_PORT` = Koda's own
port **7439** (`ABITO_ENGRAM_PORT` in the parent env overrides it for tests/embeddings),
`ENGRAM_BIN` = ONLY the pinned binary the bundled runtime manifest names, `ENGRAM_NO_UPDATE_CHECK=1`,
and NO `ENGRAM_URL`/`ENGRAM_DATA_DIR`/inherited `ENGRAM_PORT`: the store follows the engine's island
`HOME` (`<island>/home/.engram`), so the user's own Engram server and store (`7437`/`7438`,
`~/.engram`) are never read, probed or inherited. The memory project stays `abito-island`
(`<workspace>/.engram/config.json`, `ABITO_MEMORY_PROJECT` + identity pin). The daemon confirms the
private port is EMPTY before the engine spawns and owns cleanup only then; a failed or ambiguous
lookup refuses ownership (logged, the engine still starts); on daemon stop the listener is verified
against the island's `.instance-id` + `GET /health` with a stable PID before any SIGTERM — a server
that is not Koda's is never touched. **Koda 0.1 memories saved in the user's own Engram are NOT
migrated** into the island store (human decision L11); the island memory starts empty. Only Koda's
own default engine gets private memory: a custom `command` gets no memory env and no ownership.

## Continuous conversation rotation (K2-05 T3, on by default)

One continuous chat that never grows unbounded: when the open session file passes a limit, the daemon
replaces it the way Gentle Dot does (its `packages/daemon/src/rotation.ts`, MIT) and the island sees
nothing. There is no opt-in step and no visible summary frame — #386's opt-in rotation
(`thresholdPercent`/`keepTurns`, Spanish framing block prepended to the next prompt by
`promptDecorator`) is GONE: a v0.1.0 config with those keys still boots (they are ignored, with a
one-line log notice), and any other unknown `rotation` subkey is still refused.

- **Config.** The strict `rotation` key: `enabled` (strict boolean, default **true**), `bytes`
  (1024..2147483647, default 20971520 = 20 MB) and `compactions` (1..1000000, default 10). The env
  `ABITO_ROTATE_BYTES` / `ABITO_ROTATE_COMPACTIONS` overrides win over the file; only plain positive
  decimal integers are accepted (no `1e3`, `0x10` or spaces), and `ABITO_ROTATE_BYTES` keeps the same
  1024-byte minimum. An invalid env value never wins; the file/default stands.
- **Trigger.** After every natural `agent_settled` (while idle, not paused, nothing in flight) the
  daemon checks the open session file: past `bytes` of file size OR `compactions` compaction entries
  it rotates. Rotation itself issues NO model request: only `switch_session`, `get_messages` and, on
  failure, one fallback `new_session`.
- **Handoff.** The daemon writes a NEW session file next to the open one holding ONE hidden custom
  message (`customType: "abito.handoff"`, `display: false`) that carries the earlier conversation:
  the latest engine compaction summary, or — before any compaction or with an empty summary — the
  previous handoff plus the last 12 user/assistant messages truncated at 2000 chars. The seed links
  the previous file (`parentSession`), the daemon links the chain (`previousSessions`/`state.json`),
  and history keeps reading across the rotation. The engine is switched with `switch_session` and
  the daemon verifies the handoff is in the engine's context before it calls the rotation done.
  state.json only ever names a session the engine actually holds: a failed switch never leaves the
  persisted pointer at the seed.
- **Failure.** A seed-write failure, an unparseable or wrong-version session header (fail closed),
  or a failed fallback leaves the chat where it was and logs it. A failed switch or verification
  falls back to `new_session` seeded the same way (Gentle Dot's fallback), removes the orphan handoff
  file the attempt created (exactly that file), and links the fresh session into the chain — no retry
  storm: never more than one orphan seed per attempt window, and the fresh session is not oversized.
- **Prompt during a rotation.** A `send` that arrives while the switch is in flight is HELD (one per
  client, in order) and delivered once the rotation settles or fails — the user is never told to
  resend; a second prompt while one is already held still answers `busy`.
- **Guards.** Rotation is skipped while the engine is busy or not ready and while the global pause
  (#379) is active; at most one rotation runs at a time, at most one per settled turn.

## Obtaining endpoint and token (U4)

The host does not generate the token: `abito-island-daemon run` does, and publishes `{protocol, endpoint, token, pid, procStart, startedAt}`
in `<island>/runtime/session.json` (0600, removed on stop). The endpoint and token stay valid across engine restarts
(crash, workspace change, profile switch); a new daemon launch means a new token. See README "User config, CLI and host handoff".

#### Local OpenAI-compatible endpoints (v0.2)

Connect Ollama, LM Studio, llama.cpp or vLLM as a named account **without any secret on the wire**:
`local_account_create{label,accountId?,baseUrl,modelIds}` → `account` + broadcast `accounts`; change it later with
`local_endpoint_set{accountId,baseUrl,modelIds}`. Then use `models_list{accountId}` / `profile_save` / `profile_select` as for any account.

**baseUrl policy** (one validator, `validateLocalBaseUrl` in `src/protocol.cjs`): scheme `http` or `https`; no userinfo, no query, no
fragment; host exactly `localhost`, `127.0.0.0/8` in canonical dotted form, or `[::1]` (decimal/hex/octal tricks such as
`2130706433`, `0x7f.1`, `0177.0.0.1`, `[::ffff:127.0.0.1]`, `0.0.0.0` are refused); port 1–65535, explicit or default; the client must
send the **full path** (e.g. `http://127.0.0.1:11434/v1`; an empty path is refused, not guessed), matching `^/[A-Za-z0-9._~/-]*$` with no
`.`/`..` segments or `//`. The stored value is the WHATWG-normalized `url.href`. *Why*: the agent sends prompts to this URL, so it is
limited to this computer (no cloud, no LAN). **Remote endpoints and proxies are intentionally unsupported in v0.2.**

**What is stored** (private, 0600, in the account directory; none of it is ever sent to clients or logged): provider id `local-<accountId>`;
`models.json` `{"providers":{"local-<id>":{"baseUrl","api":"openai-completions","apiKey":"abito-local-endpoint","models":[{"id"}…]}}}`;
`auth.json` `{"local-<id>":{"type":"api_key","key":"abito-local-endpoint"}}`; `account.json` gains `kind:"local"`.
`abito-local-endpoint` is a fixed, **non-secret** placeholder defined in the daemon (Pi only needs *some* key to list the model; local
servers ignore it). It never comes from the client. Real keys travel only through `auth_start` / `auth_reply`, which are **refused**
(`failed`) for local accounts, as is the internal API-key enrolment, so the placeholder cannot be replaced. `account_logout` is allowed:
it clears `auth.json` (`configured:false`; `models.json` stays) and deactivates the profile if it was the active one. `local_endpoint_set` re-enables a logged-out local account: it rewrites `auth.json` with the same fixed placeholder (0600) and sets `configured:true`; no client value reaches the credential.

The hostname `localhost` is accepted and resolved by the Pi client at request time (it trusts the host resolver); `127.0.0.1` or `[::1]` is recommended. Plain http means traffic never leaves the machine.

**DTO**: the `account` DTO gains `local:true` **only** for local accounts (the key is absent otherwise); it never carries URL or models.
**`local_endpoint_set` timing**: it rewrites the account's `models.json` (and restores the placeholder `auth.json`). If the account backs the active profile the live agent files
are NOT touched: the change takes effect on the next `profile_select`. It is refused with `busy` while that account backs the active profile
and a turn or selection is in flight. `models_list{accountId}` reads the account's `models.json` through the SDK helper.

## Connector host (internal supervisor/client, H2a/H2b)

H2a/H2b add an internal `ConnectorHostSupervisor` at `daemon.connectorHost`; H2c below adds the separate `island-agent/1` control wrapper. With no `connectorHostBin`, there is no supervisor, host process or control dependency. This setting is read at daemon start; changing it requires a daemon restart. `Daemon.status()` reports `connectorHost` (`unavailable`, `stopped`, `starting`, `ready` or `restarting`) and a readiness-only `connectorHostAvailable` boolean, never the handoff token.

When configured, the daemon starts the trusted Rust binary after the engine. The host MUST be its direct child, started with `['--island', islandDir, '--parent', String(process.pid)]`, `shell:false`, `detached:false`; the host's parent guard is required because systemd user subreapers can adopt orphans. Its handoff file and private Unix socket are validated before the `abito-connector-host/1` hello completes. Control requests are available internally through the supervisor/client methods; connect values are validated, sent once, and never logged or returned. Host stdout/stderr are drained but never surfaced.

The client uses one FIFO JSONL stream, caps control frames at 256 KiB and outstanding requests at 64, and closes the stream after a timeout so a late reply cannot be mistaken for the next request. Its validated internal methods are:

| Method | Wire request fields | Sanitized result |
| --- | --- | --- |
| `status()` | `status` | `state`: protocol, pid, start time, proxy port, connector/pending counts, fail-closed flag |
| `connectors()` | `connectors` | `connectors`: schema plus allowlisted catalog and connector views |
| `pending()` | `pending` | `pending`: bounded, rebuilt approval summaries; previews are explicitly marked sensitive |
| `subscribe(enabled)` | `subscribe`, boolean `enabled` | `{ ok: true }` |
| `approve(proposalId, digest)` / `deny(proposalId)` | proposal id and, for approval, digest | `{ ok: true }` |
| `connect(id, revision, values)` | connector id, revision and validated one-way values | `{ ok: true }`; values are not retained or echoed |
| `disconnect(id, revision)` / `setEnabled(id, enabled, revision)` / `setMode(id, mode, revision)` | connector id, revision and operation-specific fields | `{ ok: true }` |
| `shutdown()` | `shutdown` | `{ ok: true }`, then host exit |

The host's `state.failedClosed` field is only the connector store's rollback-degraded flag: `failedClosed:false` is not proof that the build has a real keyring or transport. The daemon must never present `failedClosed:false` as “connectors work”; `connectorHostAvailable` reports host-process readiness only and does not establish connector functionality. The client retains the existing `failedClosed` field name for compatibility; do not invert or reinterpret it.

Protocol errors map to the closed codes `bad_request`, `stale`, `busy`, `unavailable`, `failed`, `rate_limited` and `too_large`; raw host messages and unknown reply fields are never surfaced. This is an internal API only, not an `island-agent/1` contract.

The daemon does not automatically assign `<island>/connectors/mcp-source.json` to `mcpConfigPath`. A human or installer must explicitly set that config path when the host's proxy-only MCP source should be projected. Teardown closes the H2c control adapter (cancelling an active setup prompt and removing host listeners), then requests host shutdown before stopping the engine and island server. A crash leaves host-owned files for host recovery on its next start.

## Connectors control frames (H2c)

These additive commands are available only after the authenticated `island-agent/1` hello. They are separate from `connectors_list`: that command still returns the persisted CLI view; control snapshots use the running host and their `connectors` frame has `live:true`. All newly defined request/result keys below use snake_case. Existing auth frames retain their shipped `flowId`/`promptId`/`accountId` spelling. Unknown request fields are dropped, except the forbidden setup-value keys on `connectors_connect`, which reject the entire frame as `bad_request`. Every request counts against the existing 240-frames/minute per-client limit (max four clients).

### Client → server

| type | Exact accepted fields | Validation |
| --- | --- | --- |
| `connectors_pending` | `type` | No fields. Replies to requester with a fresh `pending` list. |
| `connectors_approve` | `type`, `proposal_id`, `digest` | `proposal_id` matches the host client's `^ap-[0-9a-f]{28,}$`; `digest` is 64 hexadecimal characters, case-insensitive and normalized to lowercase. |
| `connectors_deny` | `type`, `proposal_id` | Same proposal-id grammar. |
| `connectors_connect` | `type`, `connector_id` | Connector id matches `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$` and is not `__proto__`, `constructor` or `prototype`. Any own `values`, `secrets`, `fields`, `token` or `password` key rejects the frame; no secret map is accepted. |
| `connectors_disconnect` | `type`, `connector_id` | Same connector-id grammar and reserved-name rejection. |
| `connectors_mode` | `type`, `connector_id`, `mode` | Same connector-id grammar; `mode` is `read_only` or `read_and_send`. |

Normal unknown fields are discarded and never reach the control adapter. In particular, a connect request containing a secret marker is rejected before dispatch; the server never logs request bodies.

### Server → client

- `pending` is rebuilt field by field as `{"type":"pending","items":[...]}`. Each item contains exactly `proposal_id`, `connector_id`, `connector_label`, `connector_label_truncated`, `tool`, `arguments_preview`, `arguments_truncated`, `arguments_sensitive:true`, `digest`, and `expires_in_ms`. At most 64 items; preview at most 512 Unicode characters; connector label at most 128; proposal and connector ids use the client grammars above. Invalid host data fails closed with `error{code:"failed"}`. The `connectors_pending` caller receives the current host list; all clients also receive a `pending` broadcast when the normalized proposal-card content changes, but not for expiry-countdown-only updates.
- The live `connectors` frame is the existing sanitized schema/catalog/connectors DTO plus optional `live:true`; persisted `connectors_list` omits the field. After approval, denial, disconnect, mode change or connect, every client receives the host's current connector records and the cached CLI catalog (or `catalog:[]` if the CLI catalog is unavailable). Mutating commands have no bare acknowledgement: the broadcasts are their result.
- `connectors_connect` replies to its caller with `auth_started{flowId,connector_id}`. The daemon then broadcasts the existing `auth_prompt` frame with `flowId`, `promptId`, `accountId:""`, `connector_id`, `kind:"secret"|"text"`, `message` (the field label), `secret`, and optional boolean `optional` (emitted only when supplied). Each `auth_reply{flowId,promptId,value}` answers exactly the current prompt. A successful or failed flow is broadcast as `auth_done{flowId,connector_id,ok,message?}`; for connector flows, `message` is only a closed error code. `auth_cancel{flowId}` cancels the matching flow. Account flows keep the existing AccountManager routing and frame bytes.
- Connector flows are NOT added to `auth_state` late-client recovery. A late client does not receive an existing setup prompt; the island must not infer or replay one.

Wire fields (the transport adds `seq`; the displayed order is illustrative):

```json
{"type":"pending","items":[{"proposal_id":"ap-<lower-hex>","connector_id":"notion","connector_label":"Notion","connector_label_truncated":false,"tool":"search","arguments_preview":"...","arguments_truncated":false,"arguments_sensitive":true,"digest":"<64-hex>","expires_in_ms":12000}]}
{"type":"connectors","schema":"abito-connectors/view/1","catalog":[],"connectors":[],"live":true}
{"type":"auth_started","flowId":"connector-setup-<16-hex>","connector_id":"notion"}
{"type":"auth_prompt","flowId":"connector-setup-<16-hex>","promptId":"<prompt-id>","accountId":"","connector_id":"notion","kind":"secret","message":"Access token","secret":true,"optional":false}
{"type":"auth_done","flowId":"connector-setup-<16-hex>","accountId":"","connector_id":"notion","ok":false,"message":"needs_setup"}
{"type":"error","code":"unknown_proposal"}
```

For a cancelled flow, `auth_done` may also carry `cancelled:true`; `message` is omitted or a closed code. Optional fields on the existing auth builders stay absent unless supplied. `connectors.live` is absent on persisted `connectors_list` replies.

### Bounds, safety and behavior

`pending` previews are sensitive and explicitly marked so. `arguments_truncated` preserves the host flag and is also true if the daemon removed any control/format character (including bidi marks, newline or RTL format marks): **true also means the daemon removed control/format characters, i.e. what is shown is not exactly what the digest covers**. A card with this flag must offer Deny only. The host's approval TTL is at most 30 seconds; the island computes its local deadline as frame-arrival time plus `expires_in_ms`. The host pushes a refreshed `pending` set on create, decide and expire (normally within about 50 ms); the daemon does not poll on a clock. If approval arrives after expiry, the host reports `stale`, fresh pending no longer contains the proposal, and the daemon answers `unknown_proposal`; the island displays «venció» rather than success.

Approval and denial are forwarded once and never automatically retried. After success or `stale`, the daemon refreshes both pending and connectors and broadcasts both. For stale approval, if the refreshed item is absent or has the same digest, the result is `unknown_proposal`; if it remains with a different digest, the result is `digest_mismatch`.

`connectors_disconnect` and `connectors_mode` use the current record revision; if the host answers `stale`, the daemon refetches and retries once, then maps a second stale to `busy`. `setMode` is called only for an actual `connectors_mode` request: never on start, restart, reconnect or flow completion. Moving to `read_and_send` widens what the connector may do; the island asks the human first and the click is the confirmation. The daemon applies the request as received and never pre-approves a mode change. Returning to `read_only` needs no confirmation.

Only one setup flow may be active. Catalog setup has at most eight fields; prompts are sequential and each expires after 120 seconds. An empty optional answer is omitted; an empty required answer and a prompt timeout end with `needs_setup`. Values exist only in the in-memory flow, are sent once to the host `connect(id, revision, values)` call (record revision, or `0` for a new connector), and are cleared on success, failure, cancel, timeout, host loss and daemon teardown. No values appear in island command frames other than the existing transient `auth_reply`, logs, connector DTOs, diagnostics, errors or broadcast events. The shipped host binary is FAIL-CLOSED: its `connect` returns `unavailable` until the keyring and transport work lands. `provider_oauth` is not implemented in this build and returns `unavailable` without prompts.

| error code | emitted by H2c | Meaning |
| --- | --- | --- |
| `bad_request` | yes | Invalid command or missing connector/catalog record |
| `busy` | yes | Host busy/rate-limited or a second active setup flow; a second stale mutation retry |
| `unavailable` | yes | No control/ready host, OAuth unsupported, or host unavailable |
| `failed` | yes | Unexpected host/data failure |
| `unknown_proposal` | yes | Stale proposal absent or still present with the requested digest; includes expired approvals |
| `digest_mismatch` | yes | Stale approval still present under a different digest |
| `needs_setup` | yes | Required setup answer empty, prompt timeout, or host connect `bad_request` |
| `signin_failed` | yes | Host connect failed |
| `rate_limited` | existing limiter only | Per-client frame limit; not a host decision result |
| `already_decided` | reserved, not emitted | The host collapses decided proposals into `stale`/`failed` |
| `session_mismatch` | reserved, not emitted | The host collapses this case into `stale`/`failed` |
| `pending_full` | reserved, not emitted | The host collapses this case into `stale`/`failed` |

The error enum also retains existing codes such as `not_busy` and `unknown_ask`; error strings and raw host detail are never sent.

**Grave same-UID note (next to the agents invariant).** `connectors_approve` is a privileged command reachable only through the authenticated island channel (not an MCP/engine tool, not a CLI); but the channel token lives in `<island>/runtime/session.json` (0600) and the Abito engine agent, Claude Code and Codex run as the same user and can read it: an approval card the agent can click is NOT a human gate. This matters MORE for approvals than for agents. Closing it needs the daemon launched by the island with an inherited socket (security follow-up, not done).
