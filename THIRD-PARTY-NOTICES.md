## yt-dlp: a copyleft-carrying bundle, and the same missing mirror (K2-13 T2c-8, S19)

Koda ships yt-dlp 2026.10.26, the official standalone build, to read the YouTube links a Minikoda finds in a post
(`apps/desktop-daemon/src/minikodas/youtube.cjs`). It runs it as a separate, unmodified program with command-line
arguments only; nothing of Koda is linked with it. The pin, the sha256 of every download and the licence texts it ships
are in `apps/desktop-tauri/packaging/runtime/ytdlp.sha256`; the build verifies all of it and refuses a file that is not
an official PyInstaller build.

yt-dlp itself is **Unlicense** (public domain), but its standalone executables are PyInstaller bundles that also carry
Python (PSF-2.0) and third-party components — including **copyleft** ones: GNU Readline (GPL-3.0-or-later, bundled as its
own shared object), mutagen (GPL-2.0-or-later), libidn2/libunistring/libintl (LGPL), libstdc++/libgcc (GPL-3.0 with the
GCC exception). The release publishes all of their texts in `THIRD_PARTY_LICENSES.txt`, and that file ships verbatim as
`runtime/THIRD-PARTY-NOTICES.yt-dlp.txt`; yt-dlp's own licence ships as `runtime/LICENSE.yt-dlp.txt`. Redistributing the
binary is allowed by those licences, and it does not make Koda's own code GPL (separate program, mere aggregation on the
media), but the GPL-3.0-or-later components bring the **source-access obligation**: as with FFmpeg, a download owes
GPL-3.0 §6(d) — a designated place for the Corresponding Source (the yt-dlp source at tag `2026.10.26` plus each bundled
component's own source, which yt-dlp's maintainers also provide on request), not just a written offer.

**Still missing before a public release:** Koda does not mirror those sources yet, so no designated place exists and that
obligation is unmet today; the mirror has to exist and be linked from this file and the download page. The licence review
of yt-dlp and of the copyleft components inside its standalone builds has **NOT** been done. This is an engineering
record, not legal advice.

**YouTube breaks yt-dlp regularly.** A release that stops extracting a video is a normal event: refresh the pin (tag, the
two sha256 values from the release's `SHA2-256SUMS`, the two licence texts) on a schedule, not only when something fails.

Also: YouTube's own terms do not allow downloading outside its apps. The product decision to read a link through its
subtitles, or through a downloaded audio track when it has none, was taken knowingly (decision L33).

## FFmpeg: source access, and the mirror that is still missing (K2-13, S9)

Koda ships FFmpeg (LGPL-3.0-or-later) as a separate program, running it unmodified with command-line arguments only.
Its Corresponding Source is the exact FFmpeg source at revision `c179411bbb2864cc71323d3055acda25d5c2aace` — the
commit FFmpeg's own version string labels `n9.0.2-49-gc179411bbb`, a label and not the identity — together with the
BtbN/FFmpeg-Builds scripts and the pinned library versions linked into it.

**A download owes §6(d), not an offer.** Koda reaches people as a file they download, so the clause that applies is
GPL-3.0 §6(d), incorporated by LGPL-3.0: recipients must be able to obtain the Corresponding Source from a designated
place (a network server or an equivalent) in the same way they obtained the binary, with clear directions next to the
download. A written offer to send the source on request — GPL-3.0 §6(b) — is the clause for a copy handed over in a
physical product; on its own it is **not** sufficient for a download. (And the basis is GPL-3.0 §6 as incorporated:
LGPL-3.0 §6 is «Revised Versions», and combining a work with the Library is LGPL-3.0 §4/§5.)

**Still missing before a public release:** Koda does not mirror those sources yet, so no designated place exists and
the §6(d) obligation is unmet today. The mirror must exist and be linked from this file and from the download page
before the first public release. As an additional measure — not a substitute — the maintainers also provide the source
on request for at least three years after a release ships it, for no more than the cost of making and sending the copy.
The licence review of FFmpeg (LGPL-3.0 obligations and the AAC/H.264 patent question) has **NOT** been done. This is an
engineering record, not legal advice.
The detailed text travels with every installer: `apps/desktop-daemon/THIRD-PARTY-NOTICES.md` and the runtime's
generated `THIRD-PARTY-NOTICES.md` (`apps/desktop-tauri/packaging/runtime/build-runtime.cjs`).
